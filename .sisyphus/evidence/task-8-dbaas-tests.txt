The OpenStack RHOSO DBaaS Proof-of-Concept (PoC) validation was conducted on an
AWS-based RHOSO 18.0 cluster (OCP 4.18) with 3 bare-metal EC2 compute nodes
(c5d.metal). The validation covered 36 of 37 validation items (V1–V37), with
excellent pass rates across all DBaaS lifecycle domains.

  • Total V-items assessed:     36 (+ 2 sub-items = 38 total)

                                   V14 (Capacity 2,000, design-only — no live test)

  • Validation window:            2026-05-13 → 2026-05-19

Key Conclusion (from AWS-POC-FINAL-REPORT.docx):
  "The RHOSO DBaaS architecture — Patroni PostgreSQL HA with etcd DCS, VIP
   callback-based failover, pgBackRest NFS backup, and OVN network isolation —
   is validated as functionally correct for the target production use case."

7.1 Security & Isolation (V16, V22, V23, V24, V29, V30, V31)
  • V16 Network Isolation: PASSED — 5 traffic types isolated on separate ENIs;
    tenant VM cannot reach infrastructure subnets (100% packet loss)
  • V22 Multi-tenant Isolation: PASSED — cross-tenant ICMP blocked 100%,
    TCP/5432 blocked, API isolation confirmed (tenant-b sees only own resources)
  • V23 OS Login Control: PASSED — PasswordAuthentication=no, SELinux=Enforcing,
    minimal shell accounts
  • V24 Security/Platform Audit: PASSED — pgaudit (DDL+ROLE), auditd active,
    4 distinct roles with privilege matrix
  • V29 User Separation: PASSED — dba_user, app_user, monitoring_user,
    backup_user with correct privilege boundaries
  • V30 Audit Logging: PASSED — CREATE TABLE, ALTER ROLE, slow queries,
    failed auth all logged
  • V31 Privilege Management: PASSED — non-superusers cannot escalate;
    CREATE ROLE SUPERUSER denied

7.2 Performance / QoS (V6, V7, V9, V17)
  • V6 IOPS QoS: PASSED — fio measured within ±1% of configured caps:
    db.small: 5,010 vs 5,000 (+0.20%); db.medium: 14,143 vs 14,000 (+1.02%);
    db.large: 25,275 vs 25,000 (+1.10%). Uncapped baseline: 232,000 IOPS
  • V7 RPO/Replication Lag: PASSED — 3,175 TPS sustained load, peak lag ~5.4 KB,
    zero lag within 2s after load ended. Effective RPO ≈ 0
  • V9 N-1 Capacity: PASSED — baseline 3,196 TPS vs N-1 3,271 TPS (+2.3%).
    Performance improved with one fewer replica (less replication overhead)
  • V17 Replication Load Perf: PASSED — 116,516 txns, 3,883 TPS, 1.288ms avg
    latency; post-load lag=0 on all replicas

7.3 Infrastructure Resilience (V5, V18, V26, V37)
  • V5 VM-level Recovery (Nova Evacuate): PASSED (2026-05-17) —
    evacuation mechanism works; key finding: strict anti-affinity with N=N
    blocks evacuate; local ephemeral storage = data loss (expected)
  • V18 Storage Redundancy: PASSED — RAID5 clean, 3 active + 1 hot spare,
    1.68TB usable at /var/lib/nova/instances
  • V26 CPU Resource Control: PASSED — hw:cpu_policy=dedicated enforced;
    80 PCPU dedicated cores available; no overcommit on pinned instances
  • V37 Anti-affinity Server Group: PASSED — Nova server group policy
    confirmed; VMs placed on distinct physical hosts

7.4 Operations & Data Integrity (V12, V13, V32, V35, V36)
